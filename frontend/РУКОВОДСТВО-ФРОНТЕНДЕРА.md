# Руководство фронтендера: Mini App «Общага-бот»

## Архитектура

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────┐
│  MAX Messenger    │ ←→  │   Go backend     │ ←→  │ PostgreSQL│
│  (Mini App API)   │     │   (Fiber + API)  │     └──────────┘
└──────────────────┘     └──────────────────┘     ┌──────────┐
                                ↑                  │  Redis   │
                                │                  └──────────┘
┌──────────────────┐     ┌──────┴───────────┐
│  React SPA       │ ←→  │   nginx proxy    │
│  (Vite + nginx)  │     │   /api/* → :8080 │
└──────────────────┘     └──────────────────┘
```

- **Go backend** (Fiber, порт 8080) — бизнес-логика, PostgreSQL, Redis, RabbitMQ
- **React SPA** (Vite, порт 5173 dev / nginx:80 prod) — Mini App внутри MAX Messenger
- **nginx** проксирует `/api/` на Go-бэкенд (в Docker через `host.docker.internal:8080`)
- **UI-библиотека**: `@maxhub/max-ui` (MAX-специфичные компоненты) + `react-icons/lu` (Lucide-иконки)
- **Роутинг**: `react-router-dom` v6, роль-зависимый lazy-loading (см. ниже)

## Роутинг и роли

Фронтенд использует **роль-зависимый роутинг** через `Router.jsx`. Три роли:

| Роль | Ключ | Папка страниц |
|---|---|---|
| Проживающий (студент) | `resident` | `src/pages/Resident/` |
| Сотрудник | `employ` | `src/pages/Employ/` |
| Студсовет | `stud_council` | `src/pages/StudCouncil/` |

### Как работает Router

`Router` получает `role` как пропс и lazy-load'ит страницы по маске:
```
./pages/{RoleName}/{PageName}{RoleName}.jsx
```
Например, `role="resident"` и страница `Home` → `./pages/Resident/HomeResident.jsx`.

URL-структура: `/{page}_{role}` (например `/home_resident`, `/laundry_employ`).

### Текущее состояние

В `src/index.js` роль захардкожена:
```jsx
<Router role={'resident'}/>
{/* <Router role={'employ'}/> */}
{/* <Router role={'stud_counsil'}/> */}
```

**Нужно сделать**: читать роль из query-параметров MAX Mini App или из API `/auth/me`.

### Доступные страницы (на все роли)

| Маршрут | Страница |
|---|---|
| `/home_{role}` | Главная (WelcomeBlock + кнопки) |
| `/chat-links_{role}` | Ссылки на чаты |
| `/info_{role}` | Справочная информация |
| `/room_{role}` | Комната (у проживающего) / Поиск комнат (у сотрудника) |
| `/laundry_{role}` | Стирка |
| `/cleaning_{role}` | Дежурства |
| `/cleaning_employ/room_info` | Детальная информация о комнате (только employ) |

## Auth middleware (как работает сейчас)

**Никакого JWT нет.** Аутентификация через заголовки:

### `AuthMiddleware` — идентификация пользователя
```go
// internal/api/middleware/auth.go
func AuthMiddleware(svc *service.DBService) fiber.Handler {
    userID := c.Get("X-User-ID")  // ← UUID пользователя
    c.Locals("user_id", userID)
}
```

### `RequirePermission` — проверка прав сотрудника
```go
// internal/api/middleware/rbac.go
func RequirePermission(svc *service.DBService, resource, action string) fiber.Handler {
    employeeID := c.Get("X-Employee-ID")    // ← UUID сотрудника
    dormitoryID := c.Get("X-Dormitory-ID")  // ← UUID общежития
    svc.CheckPermission(dormitoryID, employeeID, resource, action)
}
```

**Фронтенд должен передавать эти заголовки** во все защищённые запросы. Откуда их брать:
- Из query-параметров Mini App при открытии (MAX передаёт `?user_id=...`)
- Вызвать `GET /api/v1/auth/me` с `X-User-ID`, получить роль и связанные UUID

### Какие эндпоинты требуют auth

| Middleware | Где используется |
|---|---|
| `AuthMiddleware` | `/auth/me`, `/residents/:id`, `/employees/:id`, `/laundry/bookings` |
| `RequirePermission` | `/laundry/machines POST`, `/cleaning/* POST/DELETE`, `/reference-materials POST`, `/chat-links POST/DELETE`, `/controls/*`, `/modules/*` |

Эндпоинты **без middleware** (публичные): `/dormitories/:id/floors`, `/floors/:id/rooms`, `/rooms/:id`, `/rooms/:id/residents`, `/cleaning/schedule`.

## Формат ответов API

**Нет единой обёртки `{success, data}`.** Каждый эндпоинт возвращает данные напрямую:

Успех — просто JSON-объект (массив или объект):
```json
// GET /api/v1/dormitories/:id/floors
[{"id": "...", "dormitory_id": "...", "floor_number": 1}, ...]
```
```json
// GET /api/v1/cleaning/schedule?dormitory_id=...
{"data": [...]}
```

Ошибка — формат из кастомного ErrorHandler:
```json
{"success": false, "error": "описание", "code": 400}
```

## Интеграция Mini App в MAX Messenger

### 1. Регистрация в панели MAX

1. Зайти в [MAX Platform → Mini Apps](https://platform.max.ru/miniapps)
2. Создать Mini App: название, URL продакшена, иконка
3. Получить `MINI_APP_ID`

### 2. Отправка Mini App из бота

В коде бота кнопка типа `miniapp` (см. `internal/keyboards/keyboards.go` и `internal/bot/bot.go`):

```go
// В keyboards.Button добавить:
Type  string  // "miniapp"
AppID string  // ID Mini App в MAX

// В SendMessageWithKeyboard обработать:
if btn.Type == "miniapp" {
    kbRow.AddMiniApp(btn.Text, btn.Payload, btn.AppID)
}
```

**Важно**: уточнить в SDK `max-bot-api-client-go` актуальный API для Mini App кнопок.

### 3. Query-параметры при открытии

MAX передаёт параметры в URL при открытии Mini App:
```
https://ваш-домен?user_id=143554557&chat_id=...&platform=max&...
```

Фронтенд должен прочитать их и использовать для:
- Установки `X-User-ID` в заголовках API-запросов
- Вызова `GET /api/v1/auth/me` для определения роли
- Динамического выбора `<Router role={...} />`

### 4. Callback из Mini App обратно в бот

MAX WebView должен предоставлять JS SDK. **Не используйте `window.Telegram.WebApp`** — это Telegram API, не MAX. Проверьте актуальную документацию MAX по WebView API (на момент написания точный аналог для MAX не указан).

## CORS

CORS-мидлварь **отсутствует** в кодовой базе. В dev-режиме проблема решается прокси Vite, в Docker — nginx. Если фронтенд открывается в WebView MAX Messenger напрямую (не через nginx), **нужно добавить** CORS в Go:

```go
// В internal/api/router.go, перед объявлением роутов
app.Use(func(c *fiber.Ctx) error {
    c.Set("Access-Control-Allow-Origin", "*")
    c.Set("Access-Control-Allow-Methods", "GET,POST,PUT,DELETE,OPTIONS")
    c.Set("Access-Control-Allow-Headers", "X-User-ID,X-Employee-ID,X-Dormitory-ID,Content-Type")
    if c.Method() == "OPTIONS" {
        return c.SendStatus(204)
    }
    return c.Next()
})
```

## Конвенции кода

### Структура страницы

Каждая страница — это React-компонент в `src/pages/{Role}/{PageName}{Role}.jsx`. Структура:
```jsx
const PageResident = () => (
    <div style={{ minHeight: '100vh' }}>
        <Header />
        <Container style={{ flex: 1 }}>
            {/* Контент */}
        </Container>
        <Footer />
    </div>
);
```

### CSS

- Глобальные переменные в `src/styles/variables.css`
- Стили компонентов в `src/styles/{ComponentName}.css`
- Утилитарные классы (margins/paddings) в `variables.css`: `.mt-1`..`.mt-5`, `.mb-*`, `.text-center`, `.text-secondary`

### Back-навигация

На всех страницах (кроме home) Header показывает BackButton. Логика:
```jsx
const homePaths = ['/home_resident', '/home_employ', '/home_stud_council'];
const isHome = !homePaths.includes(location.pathname);
// BackButton видна только если isHome === true
```
