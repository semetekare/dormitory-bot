# Общага-бот

Чат-бот для студенческих общежитий на платформе MAX Messenger.
Помогает жителям записываться на стирку, узнавать график дежурств,
читать справки и находить чаты общежития. Сотрудникам —
управлять комнатами, жильцами, прачечной и дежурствами.

## Архитектура

```
  MySQL (EIS)           RabbitMQ              PostgreSQL + Redis
      │                     │                       │
  ┌───┴───────────┐   ┌────┴─────────┐   ┌────────┴──────────┐
  │  eis-adapter   │───│   exchange   │───│  dormitory-bot    │
  │                │   │ dormitory.eis│   │                   │
  └────────────────┘   └──────────────┘   └───────────────────┘
```

- **eis-adapter** — подключается к MySQL EIS, гонит данные через RabbitMQ
- **RabbitMQ** — транспорт. Бот получает синхронизации, а также делает RPC-верификацию
- **dormitory-bot** — PostgreSQL (свои данные), Redis (FSM, кеш, дедупликация), MAX Bot API

Бот автономен: без RabbitMQ/адаптера работает как чат-бот (прачечная, дежурства, справки).
Синхронизация с EIS запускается при поднятии RabbitMQ — бот шлёт `SyncTrigger` адаптеру
и далее каждые 30 минут для страховки.

## Стек

Go 1.23, PostgreSQL 16, Redis 7, GORM, Fiber, Viper, MAX Bot API.
Модульный монолит — один бинарник, один Docker-контейнер.

## Быстрый старт

```bash
git clone https://gitlab.irgups.ru/irgups-devolopers/dormitory-bot.git
cd dormitory-bot

cp .env.example .env   # заполнить MAX_BOT_TOKEN и остальное
docker compose up -d --build
```

Бот слушает `:8080` (Fiber API) и `:8081` (health-check).

## Запуск без EIS

Если RabbitMQ недоступен — бот стартует в автономном режиме:
верификация пользователей через EIS не работает, синхронизация не идёт,
но весь внутренний функционал (прачечная, дежурства, справки, чаты) доступен.

## Синхронизация с EIS

Бот каждые 30 минут шлёт адаптеру `SyncTrigger` с MySQL-кредами EIS.
Адаптер подключается к базе вуза и начинает периодическую синхронизацию:

| Данные | Интервал |
|---|---|
| Жители | 20 мин |
| Сотрудники | 3 часа |
| Общежития и комнаты | 6 часов |

Бот потребляет синхронизации через очереди `irgups.sync.*`, создаёт/обновляет
`User`, `Resident`, `Employee`, `EmployeeDormitoryRole`, `Dormitory`, `Room`, `Floor`.

## Верификация пользователей

Пользователь отправляет контакт → бот нормализует телефон → если номер не найден
локально, делает синхронный RPC-запрос в EIS (через адаптер, таймаут 10с).
Адаптер ищет человека в `persons` → проверяет заселение → проверяет должность.
Ответ приходит за один вызов, пользователь сразу видит меню своей роли.

## Внутренняя интеграция с EIS (старый путь)

Старый код прямой работы с MySQL EIS был удалён. Весь обмен данными идёт через
RabbitMQ + eis-adapter.

## Роли (RBAC)

6 системных ролей с предустановленными правами:

| Роль | access |
|---|---|
| `director` (Директор) | Все модули: прачечная, комнаты, дежурства, справки, чаты, модули, сотрудники, роли |
| `commandant` (Комендант) | Все модули |
| `duty_officer` (Дежурный) | Чтение прачечной, комнат, дежурств, справок, чатов |
| `assistant` (Помощник коменданта) | Чтение прачечной, комнат, дежурств, справок, чатов |
| `chairman` (Председатель) | CRUD комнат и дежурств |
| `starosta` (Староста) | CRUD дежурств |

Сотрудники из EIS с должностью «заведующий» / «комендант» / «директор» получают роль `director`.

## Mock Mode (`MOCK_MODE=true`)

Полноценный мок-режим позволяет запускать бота **без eis-adapter и RabbitMQ**,
используя заготовленные данные для всех EIS-зависимых операций.

### Запуск

```bash
# Локальная разработка — одной командой:
./dev.sh up                         # бэкенд (postgres + redis + bot)
cd frontend && npm run dev          # фронтенд (Vite :5173)
# Открыть: http://localhost:5173?role=employ

# Другие роли: ?role=resident, ?role=stud_council
# JWT живёт 30 дней. Одна авторизация — работает весь день.

# Чтобы сбросить БД:
./dev.sh reset && ./dev.sh up
```

### Dev-эндпоинты

| Endpoint | Описание |
|---|---|
| `GET /api/internal/dev/auth?role=employ\|resident\|stud_council` | JWT на 30 дней (рекомендуемый) |
| `POST /api/internal/dev/launch-token {\"phone\":\"79025643215\"}` | launch_token на 5 мин (старый способ) |

### Что даёт mock mode

- **RabbitMQ НЕ подключается** — `rmqClient == nil`
- **Верификация через EIS заменена** на поиск по мок-датасету (`internal/mock/`)
- **При старте загружаются полные мок-данные**: общежития, этажи, комнаты, сотрудники, студенты (см. `internal/mock/sync_loader.go`)
- **Идемпотентность**: при повторном запуске данные не дублируются
